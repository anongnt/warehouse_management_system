📦 Product Module Report

ระบบจัดการข้อมูลสินค้าในคลังสินค้า (Warehouse Product CRUD)

1. ภาพรวมของระบบ (System Overview)

ระบบจัดการสินค้า (Product Module) เป็นฟีเจอร์หลักของระบบ Warehouse Management System ที่ช่วยให้ผู้ใช้ที่ผ่านการยืนยันตัวตนแล้วสามารถ:

  • เพิ่ม (Create) - สร้างข้อมูลสินค้าใหม่ลงในระบบ
  • ดู (Read) - แสดงรายการสินค้าแบบ pagination พร้อมค้นหา และดูรายละเอียดแต่ละรายการ
  • แก้ไข (Update) - อัปเดตข้อมูลสินค้าที่มีอยู่ในระบบ
  • ลบ (Delete) - ลบข้อมูลสินค้าออกจากระบบอย่างถาวร
สถาปัตยกรรม: ใช้รูปแบบ Frontend (React) → API Routes → Controller → Service → Database (MSSQL)

4. API Endpoints

ทุก endpoint ต้องมี Authorization: Bearer <JWT Token> ใน Header

GET /api/products

ดึงรายการสินค้าแบบ pagination พร้อมค้นหา

Query Params:page (default: 1), limit (default: 20, max: 100), search (optional)
Response:{ success: true, data: { data: Product[], total, page, totalPages } }
Status:200 OK | 400 Validation Error | 401 Unauthorized

GET /api/products/:id

ดึงข้อมูลสินค้าตาม ID

Params:id (UUID format)
Response:{ success: true, data: Product }
Status:200 OK | 400 Invalid ID | 404 Not Found | 401 Unauthorized

POST /api/products

สร้างสินค้าใหม่

Body:{ name, sku, category, quantity, unitPrice, description? }
Response:{ success: true, data: Product, message: "สร้างสินค้าสำเร็จ" }
Status:201 Created | 400 Validation Error | 409 Duplicate SKU | 401 Unauthorized

PUT /api/products/:id

อัปเดตข้อมูลสินค้า (Partial Update)

Body:{ name?, sku?, category?, quantity?, unitPrice?, description?, status? }
Response:{ success: true, data: Product, message: "อัปเดตสินค้าสำเร็จ" }
Status:200 OK | 400 Validation | 404 Not Found | 409 Duplicate SKU | 401 Unauthorized

DELETE /api/products/:id

ลบสินค้าอย่างถาวร

Params:id (UUID format)
Response:{ success: true, message: "ลบสินค้าสำเร็จ" }
Status:200 OK | 400 Invalid ID | 404 Not Found | 401 Unauthorized

5. การทำงานฝั่ง Backend (Backend Flow)

5.1 Routes (product.routes.ts)

กำหนดเส้นทาง API 5 เส้นทาง โดยทุก route ต้องผ่าน authenticate middleware ก่อน:

router.use(authenticate);  // ตรวจสอบ JWT Token ทุก request

router.get('/',    productListValidation,   ProductController.findAll);
router.get('/:id', productIdValidation,     ProductController.findById);
router.post('/',   createProductValidation, ProductController.create);
router.put('/:id', updateProductValidation, ProductController.update);
router.delete('/:id', productIdValidation,  ProductController.delete);

5.2 Validator (product.validator.ts)

ใช้ express-validator ตรวจสอบข้อมูลก่อนถึง Controller:

  • name: ไม่ว่าง, 1-200 ตัวอักษร
  • sku: ไม่ว่าง, 1-50 ตัวอักษร, เฉพาะ alphanumeric + - + _
  • category: ไม่ว่าง, 1-100 ตัวอักษร
  • quantity: จำนวนเต็ม 0-999,999
  • unitPrice: ทศนิยม 0-999,999,999.99 (ไม่เกิน 2 ตำแหน่ง)
  • description: ไม่เกิน 1,000 ตัวอักษร (optional)
  • status: เฉพาะ 'active' หรือ 'inactive' (optional, ใช้ใน update เท่านั้น)
  • id param: ต้องเป็น UUID format
  • pagination: page ≥ 1, limit 1-100

5.3 Controller (product.controller.ts)

รับ request จาก router, ตรวจผล validation, เรียก service, และส่ง response กลับ:

  • ตรวจสอบ validationResult(req) — หากไม่ผ่านส่ง 400 พร้อมรายละเอียด field errors
  • เรียก method ของ ProductService ที่เหมาะสม
  • จัดการ error ผ่าน next(error) ไปยัง error middleware กลาง

5.4 Service (product.service.ts)

ชั้น Business Logic หลัก จัดการ:

findAll(query)

  • คำนวณ offset จาก page/limit
  • สร้าง WHERE clause สำหรับ search (LIKE %search% บน name, sku, category)
  • Query จำนวนทั้งหมด (COUNT) แยกจากข้อมูล
  • เรียงลำดับ ORDER BY created_at DESC + OFFSET/FETCH
  • คืน { data, total, page, totalPages }

create(data)

  • ตรวจสอบ SKU ไม่ซ้ำ → ถ้าซ้ำ throw ConflictError (409)
  • INSERT พร้อม status = 'active' และ timestamps = GETUTCDATE()
  • ใช้ OUTPUT INSERTED.* เพื่อคืนข้อมูลที่สร้างทันที

update(id, data)

  • ตรวจสอบสินค้ามีอยู่ → ถ้าไม่มี throw NotFoundError (404)
  • ถ้าอัปเดต SKU → ตรวจซ้ำกับสินค้าอื่น (ยกเว้นตัวเอง)
  • สร้าง dynamic SET clause เฉพาะ field ที่ส่งมา (Partial Update)
  • อัปเดต updated_at = GETUTCDATE() อัตโนมัติ

delete(id)

  • ตรวจสอบสินค้ามีอยู่ → ถ้าไม่มี throw NotFoundError (404)
  • DELETE FROM products WHERE id = @id (ลบถาวร)

7. ลำดับการทำงาน (Data Flow)

7.1 การสร้างสินค้า (Create Product)

1. ผู้ใช้กดปุ่ม "+ เพิ่มสินค้า"
   └── เปิด ProductFormModal (โหมดสร้าง)

2. ผู้ใช้กรอกข้อมูล → กดปุ่ม "สร้างสินค้า"
   └── Client-side Validation
       ├── ✗ ไม่ผ่าน → แสดง field errors ใต้ input
       └── ✓ ผ่าน → เรียก createProduct(data)

3. Frontend → POST /api/products (พร้อม JWT Token)
   └── Backend: authenticate middleware
       ├── ✗ Token ไม่ถูกต้อง → 401 Unauthorized
       └── ✓ Token ถูกต้อง → productValidator

4. Backend: createProductValidation
   ├── ✗ ไม่ผ่าน → 400 { code: "VALIDATION_ERROR", details: [...] }
   └── ✓ ผ่าน → ProductController.create()

5. ProductController → ProductService.create(data)
   └── ตรวจสอบ SKU ซ้ำ
       ├── ✗ ซ้ำ → 409 { code: "CONFLICT", message: "SKU นี้มีอยู่ในระบบแล้ว" }
       └── ✓ ไม่ซ้ำ → INSERT INTO products (status='active', timestamps=GETUTCDATE())

6. Response: 201 { success: true, data: Product, message: "สร้างสินค้าสำเร็จ" }
   └── Frontend: ปิด modal → แสดง "สร้างสินค้าสำเร็จ" 3 วินาที → refresh รายการ

7.2 การค้นหาและแสดงรายการ (Search & List)

1. ผู้ใช้พิมพ์ในช่องค้นหา
   └── Debounce 300ms (รอหยุดพิมพ์)
       └── setDebouncedSearch(search) + setPage(1)

2. useEffect(fetchProducts) ถูก trigger
   └── GET /api/products?page=1&limit=20&search=xxx

3. Backend: ค้นหาด้วย LIKE %search% บน name, sku, category
   └── เรียงลำดับ created_at DESC + OFFSET/FETCH pagination

4. Response: { data: Product[], total, page, totalPages }
   └── Frontend: อัปเดตตาราง + pagination controls

7.3 การแก้ไขสินค้า (Update Product)

1. ผู้ใช้กดปุ่ม "แก้ไข" ในแถวสินค้า
   └── เปิด ProductFormModal (โหมดแก้ไข, เติมข้อมูลเดิม)

2. ผู้ใช้แก้ไขข้อมูล → กดปุ่ม "บันทึก"
   └── Client-side Validation → PUT /api/products/:id

3. Backend: ตรวจสอบ product มีอยู่
   ├── ✗ ไม่มี → 404 Not Found
   └── ✓ มี → ตรวจ SKU ซ้ำ (ถ้าเปลี่ยน)
       ├── ✗ ซ้ำ → 409 Conflict
       └── ✓ ไม่ซ้ำ → Dynamic UPDATE เฉพาะ field ที่ส่งมา

4. Response: 200 { success: true, data: Product, message: "อัปเดตสินค้าสำเร็จ" }
   └── Frontend: ปิด modal → แสดง notification → refresh

7.4 การลบสินค้า (Delete Product)

1. ผู้ใช้กดปุ่ม "ลบ" → เปิด Confirm Dialog (แสดงชื่อสินค้า)

2. ผู้ใช้กด "ลบ" (ยืนยัน)
   └── DELETE /api/products/:id

3. Backend: ตรวจสอบ product มีอยู่
   ├── ✗ ไม่มี → 404 Not Found
   └── ✓ มี → DELETE FROM products WHERE id = @id

4. Response: 200 { success: true, message: "ลบสินค้าสำเร็จ" }
   └── Frontend: ปิด dialog → แสดง notification → refresh

12. สรุป (Summary)

ระบบ Product Module ถูกออกแบบตามหลัก Separation of Concerns โดยแยกความรับผิดชอบอย่างชัดเจน:

  • Routes: กำหนดเส้นทาง + middleware chain
  • Validators: ตรวจสอบความถูกต้องของข้อมูลนำเข้า
  • Controllers: จัดการ HTTP request/response
  • Services: business logic + database operations
  • Frontend: UI components + API integration

ระบบรองรับการทำงาน CRUD ครบวงจร พร้อม pagination, search, validation ทั้ง client-side และ server-side, error handling ที่ครอบคลุม, และการรักษาความปลอดภัยผ่าน JWT authentication
